# 禾诊 PPT 大纲（6 页 + 备用页）

> 原则：每页只回答一个问题；截图必须来自真实运行；创新点必须能落到代码。

## 第 1 页 封面

**标题**：禾诊——农作物缺素症识别与科学施肥建议智能体

**副标题**：先查本地知识，再给可解释建议

**一句话**：让每一片异常叶片都说清楚缺了什么，让每一次施肥都有依据。

**视觉**：绿色田野底图或项目首页截图；右下角放 OHCP 标识。

---

## 第 2 页 需求理解

**标题**：黄叶不一定是缺氮，施肥不能靠猜

**核心问题**

- 农户难以区分缺氮、缺钾、缺铁等相似症状；
- 盲目补肥会造成成本增加、土壤板结和面源污染；
- 大模型直接回答缺少证据，现场还可能断网。

**目标**

- 输入作物、部位、症状和环境；
- 输出多候选缺素、置信度、风险与施肥方案；
- 全链路本地可运行，结果可追溯。

---

## 第 3 页 系统方案

**标题**：前后端分离 + 本地 RAG 的可解释智能体

**架构图**

```text
HTML/CSS/JS
    ↓ POST /api/diagnose
Spring Boot REST API
    ↓
DiagnosisAgentService
    ├─ TextMatcher：本地知识检索与重排
    ├─ RiskAssessor：田间风险预警
    ├─ AdviceFactory：双版本施肥方案
    └─ QueryStatsService：现场统计
    ↓
本地 JSON 知识库 + 来源 ID
    └─ 可选：Spring AI 润色 / LangChain4j @Tool
```

**强调**

- 大模型不是核心判断器；
- 断网、无密钥也可完整演示；
- 知识库外部 JSON 支持热重载。

---

## 第 4 页 数据与 RAG

**标题**：不是“让模型猜”，而是“先找证据再组织答案”

**数据来源**

- 公开作物营养诊断科普；
- 测土配方施肥与农技推广资料；
- 化肥减量增效与绿色农业公开资料。

**处理流程**

1. 爬虫采集公开页面；
2. 去噪、清洗、切片；
3. 人工核对并结构化；
4. 写入本地 JSON；
5. 检索时按症状、部位、作物、标签和相似度重排。

**可展示数字**

- 8 类核心缺素；
- 4 类公开资料来源；
- Top 3 候选；
- 7 个自动化测试。

---

## 第 5 页 真实运行结果

**标题**：从症状到施肥建议，一条链路跑通

**截图建议**

- 左：表单输入“水稻 + 下部老叶 + 发黄 + 矮小 + 分蘖减少”；
- 中：缺氮 70%+，多候选结果；
- 右：中风险预警、四类施肥建议、来源与思政提示。

**讲解点**

- 为什么是缺氮：老叶先黄、植株矮小、分蘖减少；
- 为什么有风险：沙质土 + 降雨 + 分蘖期；
- 为什么可信：证据链、来源 ID、安全减量提醒。

## 第 6 页 创新、测试与分工

**标题**：一小时里，把“能跑”做成“可讲、可证、可扩展”

**创新点**

**测试**

- 接口层 3 个测试；

**分工**

- A 后端主链路；
- B 知识与数据；
- C 前端交互；
- D 测试部署；
- E PPT 与答辩。

**收束**

> 科学施肥、藏粮于地、藏粮于技。青年把 AI 写进田间地头，就是对科技助农最具体的回答。

## 备用页 A：检索算法说明

- 症状词命中：权重最高；
- 作物/部位匹配：增强场景相关性；
- 标签与风险因素：补充环境线索；
- 中文双字组 Dice 相似度：处理不完全一致的表达；
- 绝对分数映射置信度：避免含糊输入被强行拉高。

---

## 备用页 B：安全边界

- 不替代测土配方；
- 不提供脱离场景的万能施肥量；
- 不替代病虫害诊断；
- 建议先小面积试验；
- 需要当地农技人员复核。

---

## 备用页 C：故障兜底

- 大模型不可用：自动回退本地模板；
- 外部 JSON 不存在：回退 JAR 内置知识库；
- 外部 JSON 格式错误：启动时明确报错，避免带病运行；
- 浏览器端请求失败：显示友好错误提示；
- 现场演示固定使用“水稻缺氮”样例，结果最稳定。
